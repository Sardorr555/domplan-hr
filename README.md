# DOMPLAN HR

Приложение для приёма сотрудников и первой зарплаты: FastAPI + SQLAlchemy + PostgreSQL, адаптивный браузерный интерфейс на русском. RAGFlow — сервис разбора документов, бизнес-процесс и права контролирует собственный API.

## Запуск Windows / Docker Desktop

В PowerShell из `D:\pta\domplan HR`:

```powershell
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(32))"
# Вставьте полученное значение в POSTGRES_PASSWORD файла .env.
docker compose up --build -d
docker compose exec web python -m app.seed
```

Откройте http://localhost:8000. Seed создаёт manager@demo.local, hr@demo.local, ceo@demo.local, accountant@demo.local, superadmin@demo.local, отдел Operations. **Каждый пароль генерируется отдельно и печатается только при создании аккаунта**. Сохраните вывод в защищённом месте. Повторный запуск не сбрасывает пароли. Не публикуйте вывод. Обычные аккаунты создаются суперадминистратором через интерфейс. Демонстрационные аккаунты можно отключить после создания собственных.

API: http://localhost:8000/docs. Состояние: /api/health. База доступна только внутри сети Compose, данные сохраняются в pgdata. Не выполняйте `docker compose down -v`, если хотите сохранить данные.

## Локально без Docker

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:COOKIE_SECURE='false'
python -m app.seed
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Без DATABASE_URL используется SQLite для локальной проверки. Для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/DATABASE`. При запуске Python напрямую `.env` автоматически не загружается; задавайте переменные окружения PowerShell. Compose читает `.env`.

## Роли и этапы

| Роль | Доступ |
|---|---|
| Руководитель | Заявки своего отдела, создание и исправление на этапе руководителя, рекомендация |
| HR | Просмотр заявок, проверка документов, заключение на этапе HR, RAGFlow |
| Директор | Утверждение оклада и приёма, возврат HR, отклонение |
| Бухгалтер | Проверка после директора, возврат директору, расчёт и запись выплаты |
| Суперадминистратор | Все заявки и действия всех ролей, управление аккаунтами, общий аудит |

Цепочка: manager → hr → ceo → accountant → payroll → calculated → paid. До передачи на payroll каждый этап допускает отклонение; возврат переводит на предыдущий этап. У руководителя возврата нет. Отклонение и оплаченная заявка окончательные. Для исправления оклада директор возвращает HR, HR возвращает руководителю; после исправления согласования проходят заново. Администратор может утвердить любой текущий этап, но обязательные этапы сохраняются. Версия заявки предотвращает повторные действия из устаревшего интерфейса. История хранит автора, время UTC, заключение и переходы. Для просмотра новых изменений нажмите «Заявки и согласования».

Расчёт: gross = round(оклад × отработано / рабочих дней + премия, 2); net = gross − удержания. Денежная арифметика Decimal, округление HALF_UP. Валюта определяется вашей организацией, по умолчанию числовые суммы без конвертации. Бухгалтер вручную вводит график, реально отработанные дни и все удержания; автоматического налогового расчёта, календаря праздников и банковского шлюза нет. Повторный расчёт до записи выплаты сохраняется в истории. «Записать внешнюю выплату» фиксирует номер платёжного документа и дату — **денежный перевод не выполняется**.

## RAGFlow

Заполните RAGFLOW_URL (например адрес собственного сервера), RAGFLOW_API_KEY и RAGFLOW_DATASET_ID в .env, затем `docker compose up -d --force-recreate web`. Ключи не встроены и не передаются в браузер. Dataset предварительно создаётся в RAGFlow с настроенными OCR/embedding моделями. Используйте отдельный dataset для HR и ограниченный ключ.

HR загружает PDF/DOCX/TXT до 10 MB; API отправляет файл в dataset, запускает parsing и сохраняет ID в заявке. «Показать разбор» получает chunks после завершения обработки. Это извлечённый текст и метаданные RAGFlow, а не автоматическое юридическое заключение. Решения принимает человек. Документ отправляется во внешний настроенный сервис; локальная копия не хранится. Если запуск parsing не удался после загрузки, ID остаётся в заявке; перезапустите parsing через RAGFlow. Настройте retention, резервирование и удаление в самом RAGFlow.

Интеграция основана на официальном HTTP API: https://ragflow.io/docs/v1.0.0-rc2/http_api_reference (upload documents, parse documents, list chunks). Укажите совместимую версию сервера; реальное подключение необходимо проверить с вашими ключами.

## Проверки

```powershell
python -m pytest -q
node --check app/static/app.js
```

Тесты используют изолированную SQLite в памяти: полный маршрут, расчёт, запрет повторной выплаты, роли/отделы, CSRF, отсутствие сессии, устаревшие версии, возвраты/отклонения, неверные дни/удержания, отключение аккаунта, ограничение входа, отсутствие RAGFlow конфигурации. PostgreSQL/Compose и RAGFlow требуют отдельной интеграционной проверки в вашей среде.

## Эксплуатация

Для внешнего доступа поставьте TLS reverse proxy и COOKIE_SECURE=true; по умолчанию Compose слушает только localhost. Сессии HttpOnly/SameSite=Strict, срок 8 часов, серверное отключение, CSRF header, пароли scrypt. После рестарта сессии сохраняются. Не публикуйте базу и ключи. Аудит доступен только для чтения через API; администратор базы технически может его менять — это не неизменяемый внешний журнал. Лимит входа 8 ошибок на email за 15 минут; перед публикацией добавьте лимиты по IP и размерам запросов на reverse proxy. Нужны резервные копии PostgreSQL (`pg_dump`), проверка восстановления, мониторинг, политика доступа и хранения HR данных. Схема создаётся при первом запуске; для будущих обновлений подготовьте проверенные SQL/Alembic миграции и бэкап. Приложение не заменяет трудовой договор и обязательное оформление.
